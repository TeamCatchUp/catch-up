# 검토큐 진행 flow

안건 하나를 끝내는 길은 셋이다. 누가 어느 길을 쓸 수 있는지는
[검토큐 권한 flow](?path=/docs/flows-llm-wiki-검토큐-권한--docs)에 있고, 여기서는 그 길을 걸었을 때
무엇이 일어나는지만 본다.

| 경로            | 끝나는 방식                                    | 뒤에 남는 단계              |
| --------------- | ---------------------------------------------- | --------------------------- |
| (a) 블록별 판정 | 판정만 쌓인다                                  | 최종 내보내기를 따로 누른다 |
| (b) 전체 승인   | 판정만 쌓인다 — 카드마다 승인을 대신 눌러 준다 | 최종 내보내기를 따로 누른다 |
| (b) 전체 반려   | 판정만 쌓인다 — 카드마다 반려를 대신 눌러 준다 | 최종 내보내기를 따로 누른다 |
| (c) 비담당자    | 열람에서 끝난다                                | —                           |

(a)와 (b)는 **같은 요청**이다 — 전체 승인·반려는 미판정 카드마다 블록 판정 PUT을 병렬로 보낼 뿐이라
둘을 섞어도 막히지 않는다. 기판정 카드는 클라이언트가 보내지 않고 건너뛰므로, 판정이 시작된 뒤에도
두 버튼을 잠글 이유가 없다.

## (a) 담당자 — 블록별 경로

목록에서 안건을 고르면 중앙이 그 안건의 diff로 바뀐다. 카드마다 승인하고, 끝에 하단 바를 누른다.

<Canvas of={QueueStories.Default} />

| 자리          | 지금 상태                 | 이유                                                                                                                                                                         |
| ------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 카드 승인     | 열림                      |                                                                                                                                                                              |
| 카드 반려     | 열림 — 사유 입력을 거친다 | 사유가 필수(422)라 전체 반려의 다이얼로그를 재사용한다(전용 시안은 대기). 진입점을 닫은 배치는 [NoRejectPath](?path=/story/screens-llm-wiki-reviewqueuepage--no-reject-path) |
| 최종 내보내기 | 항상 활성                 | 미판정 블록이 남으면 서버가 409로 거절하고, 그 메시지가 토스트로 뜬다                                                                                                        |

<Canvas of={BlockDiffStories.PartiallyDecided} />

위에서 판정이 끝난 블록은 둘이다 — "재시도 정책"은 승인, "PG 점검 시간 예외"는 반려. 둘 다 접히고
액션 자리를 각자의 배지가 대신한다 — **"승인됨"과 "반려됨"은 같은 자리·같은 셸이고 아이콘과 문구만
다르다.** 어디까지 봤는지가 배지로 남고, 반려 카드는 펼치면 사유를 다시 읽을 수 있다.

## (b) 담당자 — 일괄 경로

<Canvas of={RejectDialogStories.Playground} />

전체 반려는 사유가 필수라 다이얼로그를 먼저 연다(위 버튼으로 열어 볼 수 있다). 입력한 사유는 반려되는
전 블록이 공유한다. 전체 승인에는 확인 절차가 없다.

| 액션      | 서버에서 일어나는 일                            | 큐                                     |
| --------- | ----------------------------------------------- | -------------------------------------- |
| 전체 승인 | 미판정 블록마다 승인 판정을 저장한다            | 줄이 남는다. 발행을 따로 눌러야 끝난다 |
| 전체 반려 | 미판정 블록마다 반려 판정을 저장한다(사유 공유) | 줄이 남는다. 발행을 따로 눌러야 끝난다 |

**전체 승인·반려는 발행이 아니다.** 카드 판정을 사람 대신 한 번에 눌러 주는 것이라, 돌아온 판정으로
카드가 "승인됨"·"반려됨" 배지로 접히고 하단 바는 활성으로 남는다 —
[BulkApproved](?path=/story/screens-llm-wiki-reviewqueuepage--bulk-approved)가 승인 쪽 모습이다.
발행판에서만 빠진 블록은 변경안에 자리가 없어 판정을 받을 수 없고, 일괄 전송에서도 빠진다.

한 건이라도 실패하면 성공분은 그대로 두고 실패 건수와 서버 문구를 토스트로 보인다 — 다시 읽은 상세가
어디까지 판정됐는지를 카드로 보여 준다.

최종 내보내기만 그 안건을 큐에서 없앤다. 성공하면 화면이 **다음 안건으로 넘어간다** — 마지막
안건이었으면 이전 안건으로, 그마저 없으면 빈 안내가 선다. 전 블록이 반려된 안건을 내보내면 새 판
없이 반려로 종결된다(응답의 revision 자리가 빈다).

## (c) 비담당자 — 조회

`can_review=false`면 판정 진입점 세 층이 함께 빠지고, 열람은 하나도 줄지 않는다.

<Canvas of={QueueStories.NoReviewPermission} />

| 층        | 빠지는 것      | 남는 것               |
| --------- | -------------- | --------------------- |
| diff 카드 | 승인·반려      | 좌우 본문·수정된 이유 |
| 섹션 헤더 | 전체 승인·반려 | 제목·변경 건수        |
| 하단 바   | 최종 내보내기  | 바 자체가 사라진다    |

목록·요약·미리보기는 그대로다. 층을 하나씩 떼어 본 화면은 권한 flow에 있다.

## 미리보기가 닿는 곳

헤더의 미리보기는 **판정을 반영한 제안본**을 문서 모양으로 새 탭에 연다 — 승인·미판정은 제안 내용,
반려는 발행판 내용으로 합성된다. 발행 성공 토스트의 "열기"는 발행본 문서 화면으로 간다.

<Canvas of={DocumentStories.Default} />

아직 발행된 판이 없는 문서를 열면 안내 화면이 뜬다(404 `ARTIFACT_NOT_PUBLISHED`).
[Unpublished](?path=/story/screens-llm-wiki-documentpage--unpublished)가 그 모습이고, 버튼이
`/llm-wiki/review?artifactId={id}`로 보내 그 문서의 계류 안건을 미리 골라 준다. 문구·조립은
시안이 없어 자작이다.

# LLM Wiki 온보딩 flow

위키 생성은 전역 관리자만의 동선이다. 진입 경로는 둘(대시보드에서 밀려나기·URL 직접 진입)인데,
둘 다 같은 규칙으로 걸러진다. 역할 정의는 [권한 개요](?path=/docs/flows-llm-wiki-권한-개요--docs)에 있다.

## 진입 규칙

| 상황 | 결과 |
| --- | --- |
| 전역 관리자 + 채널 0개로 대시보드 진입 | `/llm-wiki/onboarding`으로 replace |
| 전역 관리자 + 채널 1개 이상 | 대시보드 그대로 |
| 그 밖의 사용자가 온보딩 URL로 진입 | `/llm-wiki`로 replace |
| 판정에 필요한 응답이 아직 없음 | 화면을 그리지 않는다(깜빡였다 튕기는 것을 막는다) |

`replace`라 뒤로가기로 대시보드에 돌아와도 다시 튕긴다. 대신 온보딩에서 나갈 때는 돌아갈 자리가
없을 수 있어, 히스토리가 비어 있으면 홈으로 내보낸다.

## 1단계 — 위키 목적

이름·정보 카테고리·목적·문서 종류·문체를 정한다. 선택 필드는 각 목록의 첫 항목으로 시작해
빈 선택으로 열리지 않는다.

<Canvas of={PurposeStories.Default} />

서버 필수값이 덜 차면 [다음]이 잠긴다 — 보낼 수 없는 요청을 만들지 않는다.

<Canvas of={PurposeStories.NextLockedUntilRequiredFilled} />

## 2단계 — 수집 소스

연결된 채널톡 채널 중에서 소스를 고르고, 갱신 일정을 정한다. 고른 채널은 아래 표에 쌓이고
이미 고른 채널은 피커에서 빠진다.

<Canvas of={SourceStories.Default} />

채널을 하나도 고르지 않으면 잠긴다. 수집 설정은 채널마다 저장되므로 저장할 대상이 없다.
일정은 기본 선택이 있어 잠금 사유가 아니다.

<Canvas of={SourceStories.NextLockedWithoutChannel} />

## 3단계 — 확인

1·2단계 선택을 그대로 비추는 요약이다. 여기서 [완료]를 누르는 순간 처음으로 요청이 나간다.

<Canvas of={CompleteStories.Default} />

제출 중에는 잠가 중복 클릭을 막는다.

<Canvas of={CompleteStories.Submitting} />

## 이탈 확인

초기 기본값에서 하나라도 벗어났을 때(dirty)만 확인 창을 띄운다. 아무것도 건드리지 않았으면 바로 나간다 —
잃을 입력이 없는데 묻는 창은 방해다.

## 제출

요청은 두 종류이고 순서가 있다.

1. **채널 생성 POST 1회** — 이름·카테고리·목적·문서 종류·문체
2. **수집 설정 PUT N회** — 고른 채널톡 채널마다 한 번. `credential_id`가 저장 경로의 키다

2번은 1번이 성공한 뒤에만 나가고, 일부가 실패해도 되돌리지 않는다. 채널은 이미 만들어졌으므로
성공 경로로 두고 실패한 개수만 토스트로 알린다.

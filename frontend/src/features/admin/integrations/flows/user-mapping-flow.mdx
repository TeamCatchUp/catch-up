# 이용자 매핑 flow

커넥터 쪽 계정(Github·Jira·채널톡 계정 등)과 CatchUp 이용자를 잇는 매핑을 관리하는 화면이다.
매핑이 있어야 "누가 무엇을 했는지"가 사람 단위로 연결된다.
[커넥터 연결 flow](?path=/docs/flows-커넥터-연결--docs)의 후속 단계다.

여정은 "보기 → 고치기 → 저장하기" 한 사이클이다:

1. **진입** — 등록 현황을 훑고 매핑 상태로 거른다
2. **편집 모드** — 행 단위로 매핑을 고친다
3. **저장과 부분 실패** — 협업툴 단위로 나눠 저장하고, 성공분은 유지한 채 전체를 다시 저장한다
4. **CSV 필요 빈 상태** — 매핑 원본이 없으면 업로드부터 한다

## 1. 진입

위에서부터 통계 카드 → 필터/액션 한 줄 → 매핑 표 → 페이지네이션.
통계 카드는 표시 전용이다(클릭 동선 없음). 필터는 매핑 상태 칩(전체 이용자·전체 연동됨·일부 미연동)과
채널톡 칩으로 나뉘는데, 채널톡 칩은 상태 필터가 아니라 표를 채널톡 1열로 좁히는 뷰 필터다.
액션 바에서 SSO 동기화·DB 동기화·CSV 업로드·수정 모드 진입을 할 수 있다.

## 2. 편집 모드

액션 바의 [수정]으로 진입한다. 각 행의 커넥터 셀이 드롭다운으로 바뀌어
계정을 다시 고르거나 "미사용"으로 지정할 수 있고, [저장하기]/[취소]로 빠져나온다.

## 3. 저장과 부분 실패

이 화면의 실패 처리 원칙은 "전부 롤백"이 아니라 **성공분 유지**다.

- 편집 모드의 저장은 행별이 아니라 협업툴(vendor) 단위다. 이용자별 override를 협업툴별로
  묶어 PATCH 배치를 만들고 `Promise.allSettled`로 결과를 모은다(`useUserMappingEdit`).
  성공/실패는 협업툴 단위로 갈리고, 일부만 실패하면 수정 모드를 유지해 전체를 다시
  저장할 수 있다 — 같은 값을 다시 보내도 멱등이라 무해하다. 토스트는 "N/M개 협업툴
  저장 성공"으로 진행 상황을 알린다.
- 동기화 부분 실패 배너(`MappingSyncNotice`의 `partial-failure` variant)는 컴포넌트로는
  준비돼 있지만, 화면에는 아직 배선되지 않았다 — `UserMappingView`가 지금 렌더하는
  배너는 매핑 데이터가 하나도 없을 때 뜨는 `csv-required` variant뿐이고, 동기화 배선은
  API가 확정된 뒤로 미뤄져 있다.

아래 Canvas는 배너가 준비된 상태를 보여준다 — 실제 화면에 지금 뜨는 배너는 아니다.

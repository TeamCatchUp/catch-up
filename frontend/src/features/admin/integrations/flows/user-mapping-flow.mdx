# 이용자 매핑 flow

커넥터 쪽 계정(Github·Jira·채널톡 계정 등)과 CatchUp 이용자를 잇는 매핑을 관리하는 화면이다.
매핑이 있어야 "누가 무엇을 했는지"가 사람 단위로 연결된다.
[커넥터 연결 flow](?path=/docs/flows-커넥터-연결--docs)의 후속 단계다.

여정은 "보기 → 고치기 → 저장하기" 한 사이클이다:

1. **진입** — 등록 현황을 훑고 매핑 상태로 거른다
2. **편집 모드** — 행 단위로 매핑을 고친다
3. **저장과 부분 실패** — 성공분은 반영되고 실패분만 재시도한다
4. **CSV 필요 빈 상태** — 매핑 원본이 없으면 업로드부터 한다

## 1. 진입

위에서부터 통계 카드 → 필터/액션 한 줄 → 매핑 표 → 페이지네이션.
통계 카드는 표시 전용이다(클릭 동선 없음). 필터는 매핑 상태(전체/완료/미완료) 칩과
채널톡 칩으로 나뉘는데, 채널톡 칩은 상태 필터가 아니라 표를 채널톡 1열로 좁히는 뷰 필터다.
액션 바에서 SSO 동기화·DB 동기화·CSV 업로드·수정 모드 진입을 할 수 있다.

## 2. 편집 모드

액션 바의 [수정]으로 진입한다. 각 행의 커넥터 셀이 드롭다운으로 바뀌어
계정을 다시 고르거나 "사용 안 함"으로 지정할 수 있고, [저장하기]/[취소]로 빠져나온다.

<Canvas of={Screens.EditMode} />

### 주요 분기

**커넥터 필터가 걸린 표** — 채널톡 칩으로 좁힌 1열 상태에서도 편집 규칙은 같다.

<Canvas of={MappingTableStories.ConnectorFiltered} />

## 3. 저장과 부분 실패

이 화면의 실패 처리 원칙은 "전부 롤백"이 아니라 **성공분 유지**다.

- 편집 모드의 저장은 행별로 개별 처리된다(`useUserMappingEdit`, `Promise.allSettled`).
  성공한 행은 즉시 반영되고, 실패한 행만 남아 다시 저장할 수 있다.
- 동기화가 부분 실패하면 표 위에 배너가 떠서 마지막 동기화 시각을 보여주고,
  [동기화 재시도]로 실패분만 다시 시도한다.

<Canvas of={MappingSyncNoticeStories.PartialFailure} />

## 4. CSV 필요 빈 상태

매핑 원본이 하나도 없으면 표가 비고, CSV 업로드를 유도하는 안내가 뜬다.
사용자가 해야 할 일은 CSV 업로드 또는 동기화 실행이다.
